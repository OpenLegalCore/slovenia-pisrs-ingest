# PIKI PostgreSQL and Qdrant data contract

**G2 candidate for owner review.** Database `pisrs_staging`, schema `pisrs`, PostgreSQL 18. The [API](PIKI-PISRS-API.md) defines source facts. The schema below defines intended migrations, not installed objects.

## PostgreSQL model

In the table below, columns are required unless marked `?`. FK = foreign key, UQ = unique, PK = primary key, CK = check. Internal `bigint` IDs use identity columns. Digests are `bytea` with a 32-byte length check. Timestamps are `timestamptz` in UTC, legal dates are `date`, identifier strings use deterministic bytewise collation and preserve case and leading zeros. FKs use restrictive deletion by default. Check status fields against the states specified below or in [SYNC](PIKI-PISRS-SYNC.md). Attempt results use OPEN/HTTP_COMPLETE/HTTP_INCOMPLETE/TRANSPORT_ERROR/CONTRACT_ERROR/BODY_WITHHELD, occurrence validation uses VALID/QUARANTINED, parse state uses READY/QUARANTINED and index member state uses EXPECTED/WRITTEN/VERIFIED. All tables live in `pisrs`. Use only DB-generated ingest times for audit timestamps, and store upstream legal dates separately.

Raw HTTP entity means original application body octets with content coding, without TLS or chunked transport framing. Request `Accept-Encoding: identity`; if a coding is returned, store the received coded bytes and header, then decode separately with hard encoded and decoded size limits. Store full successful bodies including all envelope keys and root array elements. Safe error metadata is always recorded. Archive complete error bodies only when source rights and sanitization permit, using explicit `BODY_WITHHELD` otherwise. Never record authorization headers, cookies, credentials, or uncontrolled exception strings. `jsonb` is a query projection. A strict JSON reader detects duplicate keys, NULs and illegal types before JSONB conversion. Commit the raw body even if projection fails, record its failure, and keep that scope out of promotion. Use integer-preserving JSON and a versioned canonical serializer for value hashes (sorted keys, original sequence for arrays, lossless decimals, no Unicode normalization). JSON pointers use RFC 6901.

Namespaces are `RS_ACT`, `RS_NPB`, `LS_ACT`, `LS_NPB`, `EU`, `CODE_LIST`, `CODE_VALUE`. Normalize spec int64 IDs to canonical decimal text after exact integer validation. Retain the lexical source value in raw bytes. CELEX uses the original nonempty string. Projection and detail membership keep distinct endpoint provenance. Alternate IDs are time-varying attributes, no unique index or rewrite of old keys. A corrected numeric identity is a new record plus reviewed lineage evidence. Inferred NPB amending SOP, base SOP and ordinal are stored under the chosen rules revision in `reference_resolution.evidence` as `amending_sop`, `base_sop`, `version_ordinal` and `rule`, with literal null for unavailable values and `version_ordinal` a positive integer when present. A single raw record may yield new parse/resolution revisions without replacing earlier work. The supported definition of archival history is all observable versions and byte revisions since first acquisition plus all retrievable upstream NPB history at the accepted source boundary.

Operational constraints that span tables must be enforced in a transaction and independently audited. These include attempt/run/source provenance, eligible artifact-to-locator and response alignment, one coherent membership manifest, legal classification rules, finite vectors and generation completeness. Migrations introduce database/roles, archive and registries, typed reconciliation, parser and text tables, then index ledger. Apply each migration with lock and version/hash reconciliation. Back up before any migration that changes persisted semantics. Do not delete history to roll back a parser/schema interpretation.

## Qdrant contract

**Candidate policy for approval.** Use `text-embedding-3-large` at 3,072 dimensions with Cosine and one unnamed float32 dense vector. Publish through alias `pisrs_piki_staging`, using physical names `pisrs_piki_staging_g_<32 lowercase UUID hex>`. Each published generation is immutable. A shadow physical collection is used during generation replacement, then removed after the reader grace window and backup verification. A no-change manifest does not build a shadow. Keep the two-generation disk/restore budget in [Operations](PIKI-PISRS-OPERATIONS.md). [Qdrant collections](https://qdrant.tech/documentation/manage-data/collections/) · [OpenAI embeddings](https://developers.openai.com/api/docs/guides/embeddings)

Recommend the latest eligible state text for each uniquely resolved current act as the first index. Apply the accepted legal-status and effective-as-of rules. Use an NPB that applies at the cutoff, or a verified base text when the approved scenario calls for one. An ambiguous link, ambiguous current status or ambiguous ordering is an explicit eligibility exception. The owner can instead index verified historic versions with required date/as-of and history filters. Historical indexing adds chunk tokens, time, space and query ambiguity. Either choice keeps all source history in PG. Owner approval is required for this policy, base fallback, effective/application cutoffs and any metadata exposed to staging users.
