# Source and index synchronization

**G2 candidate.** Every run pins the [API revision](PIKI-PISRS-API.md), [data/rule revision](PIKI-PISRS-DATA.md), release commit and a UTC work boundary. Acquire a per-stage advisory lock on a dedicated DB connection and a shared backup fence before doing work. Losing either DB session stops dispatch; the durable run ledger allows restart. The active PUBLISHED source run and index generation are independent verified checkpoints. The global backup fence and the QA publication fence are separate locks. Work queues and leases describe progress independently of success checkpoints.

## Attempts and retries

1. Dispatch only approved operations for the current service and pin the origin. Capture each attempt before dispatch. Use separate connect/read timeouts and an overall deadline, private bounded spooling, initial per-response ceilings of 64 MiB received and 256 MiB decoded with separately approved measured overrides and validated JSON or HTML shape. Save a complete source body and response provenance before advancing its work item. Reject auth/error pages presented as successful legal text.
2. For a GET interrupted by timeout, network error, 429, or retryable 5xx, use at most four attempts per lease, exponential backoff with jitter, and honor a longer valid `Retry-After` by deferring to the next permitted slot. Proposed initial 10 s connect/90 s read timeout and retry backoff 1–30 s, subject to source rules. 401/403/407/498, a TLS trust error and unexpected redirects stop dispatch and alert. A source-reported wrapper error, MIME mismatch or invalid body quarantines that response. Raw bodies are capped and captured under the [data rules](PIKI-PISRS-DATA.md#postgresql-model). Record status, attempt time, request locator, hash/length where available and safe diagnostics. No credentials, body text, URLs with secrets or dumps in logs.
3. Document dispositions are `IMPORTED`, `UNCHANGED_VERIFIED`, `SOURCE_NOT_AVAILABLE`, `NOT_SUPPORTED_BY_API`, `ACCESS_FORBIDDEN`, `RETRY_PENDING`, `QUARANTINED`. Only the first two and source-proven dispositions accepted for the revision can close required work. A 404 needs the correct authorized locator class and accepted evidence of absence. An outage, unknown mapping, unauthorized request, parser failure or QoS limit is open work. For local/EU full text use the reviewed integration-scope limitation with provenance, never probe with guessed state/portal IDs.
4. Enforce issuer budgets with one initial in-flight request and a configured pacing interval, explicit per-day request/byte/deadline ceilings, and resumable lease expiry. A capped sweep or deferred item is INCOMPLETE. Increase bounds only within the approved grant and measured resource budget.

## Enumeration and publication

1. Check the official contract hash, grants, storage budget and role/target preflight. Start or resume a run against the last published generation. Enumerate all 13 paged catalogues, all 10 complete `/seznam` arrays, the code-list catalogue and every advertised per-ID code list. Enqueue version classes and text locators after metadata capture. Fill the ordered coverage manifest for all read operations, including specific documented exceptions. Stream arrays to bounded scratch, validate closing JSON and preserve the entire body. Persist page and per-list completion only with body hash and parsed validation outcomes.
2. Use an endpoint-specific paging profile with proven progress and terminal controls. Start at page 1, use a fixed accepted page size and continue past short pages until the proven terminal boundary. Treat `totalCount` as diagnostic only. The bounded G1 pilot exercises early and terminal behavior without a full scan. G3 verifies the whole sweep against independent evidence. Check echoes, within-sweep overlap and repeats, wrappers, caps and progress. A shifted sweep restarts inside the permitted window; an unexplained empty page, bad boundary or work cap prevents publication. [Bounded pilot](PIKI-PISRS-API.md#bounded-g1-closure)
3. Produce an ordered manifest per endpoint of canonical qualified identity and payload digest, including provenance and a deterministic membership hash. Preserve duplicates and variants in observations, then decide whether a repeated identity is a legitimate cross-endpoint membership or an intra-endpoint anomaly. Compare full detail and list sets using the agreed identity and common fields, independently of order. Where the operator documents different inclusion rules, compare the expected projection computed under that rule; unmapped differences block promotion. For NPB/EU and any source with no complete independent reference, perform a second authorized sweep in the same stable window. Prefer an issuer-issued revisioned snapshot/export for independently checking all collections and use sample or repeated sweeps to detect drift. Two equal sweeps provide bounded consistency evidence. Without a snapshot or documented stable window, immutable point-in-time completeness remains NOT_VERIFIED. Compare source coverage to PostgreSQL by streamed key and body hashes from independent readers, then commit the sealed manifest.
4. Resolve references from each canonical observation. Rebuild candidate sets for MOPED, CELEX and dictionary-scoped code IDs and SOP lineage. For conforming NPB numbers, separately keep amending SOP, base SOP and inferred ordinal, and retain nonconforming numbers raw. Use a unique corroborated mapping to establish a link. Recompute relations for inflight membership, preserving prior decisions. For a changed MOPED-PLUS/EDA/SOP on the same numeric ID, compare both stable sweeps, check conflicts against active candidates, separate a corroborated correction from reassignment or collision, record prior and new values, and promote only under an accepted rule. An unresolved collision gets a quarantined event and retains the last trusted relation for served data while alerting. The rest of the run continues archival work, but the published checkpoint stays fenced for any unresolved required scope. A corrected numeric ID is separate with reviewed lineage. Never retarget an existing version FK from one conflicting observation.
5. Derive candidate locators for documented state base acts and state NPBs. Establish a source-space/control before enabling each class and preserve scope exceptions. Fetch all required available variants in the initial run, store MIME and hash and retain each distinct byte revision. Recheck an unchanged locator by a validated conditional GET only when validators were proven to cover its whole representation. Otherwise queue a deterministic full recheck cycle under the issuer rate; record this freshness boundary per ID. Coverage for a nightly claim spans only IDs validated as of that cycle, or verified upstream change signals. A new upstream NPB does not erase earlier variants. A body change at the same ID produces another immutable artifact even if title/date/number did not change.
6. Parse only after archive commit. Decode with versioned charset rules and record MIME, charset and warnings. Emit sections and provision hierarchy in source order. Visit each text-bearing node once, preserve article/paragraph labels, preambles, footnotes, table rows/cells with spans, annexes, lists, internal links and alternate headings. Record a structural locator and byte offsets if the parser can prove them. Preserve DOM fragments via original bytes, and reject unsupported formats or unresolved critical fidelity failures from normalized publication. Compare synthetic and permitted fixtures by their declared expected structure. A parse failure leaves original bytes available in the archive.
7. Select at most one validated occurrence per run, operation and qualified record, and keep every other observation. Seal per-operation/sweep digests and proof summaries in the run. For absent catalogue membership, record evidence only after terminal enumeration and stable set comparison. Keep the archived record and prior memberships. Promote audited retirement after an accepted confirmation window and sufficient independent evidence. No inference from a partial fetch. Compute separate digests for catalogues, code lists, expectations, resolved/unresolved edges, raw text, parses and archived history. Publish an eligible SOURCE run and its evidence hash in one PG transaction after the full checklist, marking the previous published run SUPERSEDED with predecessor compare-and-swap. Future incomplete runs cannot hide the latest trusted source or qualify for index publication.

### Nightly restart and changes

Each timer run executes these same rules. In the absence of a tested changed-since feed, plan complete metadata verification within the approved source window. Nightly can resume text and parsing jobs at the last committed work item, and incomplete sweep page evidence remains archived. Do not resume a split enumeration across an upstream refresh without reconciling the entire collection. Use accepted validators or an explicit complete rolling text refresh period; measure staleness per locator. Route long initial or backlog processing through the same bounded ledger, with no checkpoint advance for incomplete scope. The run report states the cutoff, missing and ambiguous scopes, last successful publication, oldest outstanding item, expected vs archived hashes, and evidence for each disposition.

## Embedding planning and delivery

1. Freeze one published SOURCE run, chosen legal-time/index policy and parser/chunker version. Walk ordered blocks into UTF-8 chunk text, retaining legal headers. Candidate target 768 tokens and hard maximum 1,024 under the pinned tokenizer, no overlap in v1. Pack whole paragraphs/rows where possible. Split oversized blocks at deterministic sentence then token boundaries that preserve complete Unicode characters and at least one source span per segment. Include ordered spans, block locators and labels in payload provenance. Reconstruct all eligible normalized text by spans and verify coverage before pricing.
2. Use the pinned local `cl100k_base` tokenizer for the candidate model. Normalize NFC and line endings for chunk content under the chunker version, retain all original text bytes and compute SHA-256 of exactly the UTF-8 model input. Reuse only a validated PG result keyed by exact text/model/dimensions. Sum token counts over distinct missing cache keys. Record provider tariff date, mode/currency, rate and formula `tokens × USD per million / 1,000,000`. Compare post-call provider usage with reservation. Any real price quote waits for actual approved eligible chunks and current tariff. Embeddings disabled by default.
3. Approval binds the frozen plan hash, model/mode/scope, token and USD caps, deadline and data-transfer permission. Before sending, transactionally reserve budget, claim input keys, and persist request hash and ordinal mapping. Commit SENT and its reserved item/ordinal map before external I/O. On restart a SENT row without recorded completion is UNKNOWN. Never auto-repeat an ambiguous paid POST. After a response validate exact index permutation, model, dimensions, finite nonzero vectors and item count, then atomically store result vectors, hashes and usage with the successful request state. Timeout, disconnect, partial response or crash after dispatch enters UNKNOWN and retains reservation. Reconcile provider request/usage evidence before deciding retry; if certainty is impossible, manual approval of exceptional reissue and budget is required. A proven rejection can release claims under the ledger policy. Publish zero cached-input repeat calls on normal retries and disclose any explicitly approved exceptional reissue separately.
4. Persist generation manifest with each eligible point and retrievable PG vector. If input remains unapproved, incomplete or rejected, retain the old INDEX checkpoint and its published collection contents. Source publication can continue. Missing vectors block promotion rather than weakening coverage.

## Qdrant publication

1. Compute the deterministic difference between the sealed candidate and published PG manifests for `pisrs_piki_staging`. Before mutation ensure every candidate vector is validated in PG. A manifest with identical content and contract requires readback but no writes or paid requests. While planning or fetching embeddings, the previous index can serve.
2. Take the exclusive QA publication lock and persist the candidate state APPLYING before the first Qdrant write. The supported QA command takes the shared lock, tests for APPLYING, reads the published manifest and cross-checks the requested date in PG before returning results. An abandoned session releases its lock but the durable APPLYING marker still prevents serving. If APPLYING is absent and a previous generation remains PUBLISHED, the fence can reopen. Never serve a mixture of revisions.
3. Apply idempotent upserts and exact inspected surplus-ID removals with write acknowledgment on this project-owned collection only. Validate collection config, complete ID set, payload values/types and exact provenance, actual dimension/finiteness and float32 vectors. Because Qdrant normalizes on Cosine writes, compare normalized values against PG under fixture-tested tolerances (pilot max absolute error `2e-6`, cosine error `1e-6`). Require terminal scroll with no cycles and zero missing, duplicate, surplus or mismatched points. Commit the new PUBLISHED head and mark the old generation RETIRED inside one PG transaction; then release the read fence.
4. On failure or crash during APPLYING, keep the read fence closed. Reacquire the exclusive lock, inspect the actual collection and resume the exact candidate diff, or rebuild the previous verified manifest using cached PG vectors. Finish with full parity, then seal the reconciled head and clear APPLYING. If a full rebuild is necessary, include measured maintenance duration in G5 acceptance.
